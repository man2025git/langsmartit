Introduction

HTML (HyperText Markup Language)

Html คือ เป็นภาษาที่ใช้สําหรับสร้าง เว็บเพจ (webpage) โดยมีคำย่อมาจาก HyperText Markup Language โดย Tim Berners-Lee เป็นผู้พัฒนา เวอร์ชันแรกของ html เริ่มใช้ในปี 1993 ปัจจุปัน html ถึง เวอร์ชัน 5

เว็บเพจ (webpage) คือหน้าต่างที่สามารถแสดงข้อมูลตัวเลข ตัวอักษร รูปภาพ เพลง หรือวีดีโอ โดยในทุกหน้างต่างที่มีข้อมูลเหล่านี้ภายในเว็บไซต์นั้น จะถูกเรียกว่า webpage ซึ่งสร้างด้วยภาษา HTML (Hyper Text Markup Language) เป็นโครงสร้าง และมีภาษาอื่น ๆ เข้ามามีส่วนเกี่ยวข้องตามความต้องการของเจ้าของเว็บไซต์ซึ่งอาจจะทำเอง หรือจ้างผู้พัฒนาเว็บไซต์ ภาษาเหล่านี้ได้แก่ ภาษา PHP ภาษา SQL เป็นต้น

เว็บไซต์ (website) คือสื่อนำเสนอข้อมูลบนเครื่องคอมพิวเตอร์ หรือคือการรวบรวม หน้าเว็บเพจหลายหน้า ซึ่งเชื่อมโยงกันผ่านทางไฮเปอร์ลิงก์ ซึ่งต้องเปิดด้วยโปรแกรมเฉพาะทางที่เรียกว่า Web Browser

ไฮเปอร์ลิงก์ (hyperlinks) คือ การเชือมไปยังหน้า webpage อื่นๆ ที่ผู้อ่านสามารถเข้าถึงได้ทันที

HyperText คือ ข้อความที่แสดงบนจอคอมพิวเตอร์หรืออุปกรณ์อิเล็กทรอนิกส์ อื่นๆ

Markup คือ Markup หรือ markup language คือ ภาษาคอมพิวเตอร์ ซึ่งเป็นภาษาที่แสดงข้อมูล โครงสร้าง รูปแบบ ตลอดจนข้อมูลอื่นๆ ที่เกี่ยวข้องไว้ด้วยกัน ซึ่งส่วนนี้เรียกว่า มาร์กอัป ส่วนมากจะพบในรูปของ tag ตัวอย่างภาษามาร์กอัป เช่น GML, SGML, HTML, XML เป็นต้น

เว็บเบราว์เซอร์ (Web Browser) คือ โปรแกรมที่ใช้แปลงภาษา HTML แล้วแสดงผลเป็นหน้าเว็บเพจ และ Web Browser ที่ได้รับความนิยมในปจจุบัน คือ Google Chrome , Firefox , Safari , Microsoft Edge เป็นต้น

โครงสร้างภาษา HTML

คือ การประกาศว่าเว็บเพจที่ได้สร้างขึ ้นมาอ้างอิงตามมาตรฐาน html version 5

คือ การประกาศภาษา (lang ย่อมาจาก languages) ว่าเนื้อหาของเว็บเพจเป็นภาษาอังกฤษ (en) เป็นหลัก

แอตทริบิวต์ (Attribute) คือ ส่วนที่ใช้กำหนดคุณสมบัติเพิ่มเติมให้กับ HTML Element ต่างๆ โดยจะอยู่ใน Tag เปิดของ Element นั้นๆ Attribute จะมีรูปแบบเป็นคู่ของ ชื่อ (name) และ ค่า (value) เช่น name="value"

แวยู่ (Value) คือ ข้อมูลที่เจาะจงถึงคุณสมบัติที่ attribute นั้นต้องการควบคุมหรือกำหนดให้กับ HTML element มีค่าเป็นอะไร หรือ เท่าไร

จากตัวอย่าง lang เป็น Attribute โดย Value คือ en

HTML element คือ คําสังที่อยู่ระหว่าง แท็ก (Tag) เปิด และ แท็ก ปิด

เช่น Document

แท็ก (Tag) คือ คำสั่งพิเศษที่ใช้ในการกำหนดโครงสร้างและลักษณะการแสดงผลของเนื้อหาบนหน้าเว็บเพจ Tag จะถูกเขียนอยู่ใน เครื่องหมายน้อยกว่า < และเครื่องหมายมากกว่า>

เป็น แท็ก (Tag) เปิด คือ จะเริ่มต้นด้วยเครื่องหมาย < ตามด้วยชื่อของ Tag และปิดท้ายด้วยเครื่องหมาย>

เป็น แท็ก (Tag) ปิด คือ จะมีลักษณะคล้ายกับ Tag เปิด แต่จะมีเครื่องหมายสแลช (/) อยู่หน้าชื่อ Tag

Document ในที่นี้ไม่ได้แปลว่า เอกสาร แต่ หมายถึง การนำหัวข้อบทความไปแสดง บน title bar ของ Web Browser ถ้าพิมพ์คำว่า "Document" ก็จะแสดงตามตัวอย่างในภาพ

หรือ Meta tags เป็นข้อความที่เราประกาศเอาไว้ใน Code จะไม่แสดงผลในเว็บเพจ แต่จะเป็นส่วนสำคัญ ในการจัดอันดับบัญชีเว็บ โดยเป็นเนื้อหาที่เกี่ยวกับเว็บไซต์ , Keywords ที่ใช้ที่เกี่ยวข้อกับเว็บไซต์ Search Engine จะทำการเก็บรายละเอียดพวกนี้ไว้อ้างอิงเว็บไซต์เรา โดย tag จะอยู่ภายใน tag เสมอ

คือ จะบอกชุดตัวอักษรที่ใช้กับภาษาไทย ให้กับ Web Browser ใช้ชุดตัวอักษร UTF-8 สำหรับเปิดเว็บเพจ (Attribute คือ charset มี Value เป็น UTF-8)

Charset:นี่คือ แอตทริบิวต์ (Attribute) ที่แจ้งให้ Web Browser ทราบว่าจะใช้การเข้ารหัสอักขระใดเพื่อให้ Web page นี้แสดงเนื้อหาตามที่ต้องการ

UTF-8:เป็น แวยู่ (Value) ของ Attribute Charset ซึ่งชุดอักขระ UTF-8 ครอบคลุมอักขระและสัญลักษณ์ทั้งหมดที่มีอยู่ในโลกนี้ ดังนั้น อักขระและสัญลักษณ์จะแสดงในหน้า Website หรือ หากต้องการใช้อีโมจิ ก็สามารถแสดงในหน้า Website ได้

มี 3 Attribute ดังนี้ name , content และ initial-scale

Attribute name="viewport" คือ ใช้สำหรับกำหนดการตั้งค่า Viewport สำหรับอุปกรณ์มือถือ เพื่อควบคุมขนาดและการปรับสเกลของหน้าเว็บ

Attribute content="width=device-width คือ กำหนดให้ความกว้างของวิวพอร์ตเท่ากับความกว้างของอุปกรณ์

Attribute initial-scale=1.0 คือ กำหนดระดับการซูมเริ่มต้นเป็น 1

โครงสร้างภาษา HTML จะแบ่งออกเป็น 2 ส่วน ได้แก่ ส่วน head และส่วน body

head คือ เป็นส่วนที่อยู่ภายใน ใช้สําหรับอธิบายข้อมูลเกี่ยวกับเว็บ เช่น ชื่อเรื่องของเว็บเพจ (Title) ชื่อผู้จัดทําเว็บ (Author) คีย์เวิร์ด (Keywords) เพื่อใช้สําหรับให้ผู้ใช้ค้นหาข้อมูลเกี่ยวกับเว็บได

body คือ เป็นส่วนที่อยู่ระหว่าง <body>...</body> ใช้อธิบายเนื้อหาหลักของเว็บ เช่น ใส่ข้อความต่างๆ รูปภาพ แบบฟอร์ม วิดีโอและยังสามารถกําหนดคุณสมบัติ พื้นฐานของเว็บได้ เช่น รูปแบบของพื้นหลัง สีของตัวอักษร

message or element content

เมสเสจ (message) คือ ข้อมูล หรือ คำ หรือ ประโยค หรือ ข้อความ หรือสารที่ถูกส่งจาก website ไปยังผู้อ่าน นั้นเอง หรือ บางครั้งจะใช้คำว่า อิลิเมนต์ คอนเทนต์ (element content) แต่ในบทความนี้ จะใช้ คำศัพย์ สลับไปมา เพื่อความเหมาะสม กับแต่ละเรือง แต่ทั้ง 2 คำนี้มีความหมายเหมือนกัน

นักพัฒนาซอฟแวร์ (Software Developer) หรือ (programmer) มีวิธีการที่สามารถเขียน message ได้ดังนี้

  • ข้อความคงที่ (Static Text) คือ Developer สามารถเขียน message โดยตรง แต่ต้องอยู่ใน tag <body> message </body>

  • ใช้แท็กเนื้อหา (Content Tags): นี่เป็นวิธีพื้นฐานที่สุด โดยการใส่ข้อความที่ต้องการแสดงไว้ภายในแท็ก HTML ต่างๆ เช่น <p> message </p> หรือ <h1> ถึง <h6> เป็นต้น
  • การใช้ JavaScript เพื่อจัดการและแสดงข้อความ (รายละเอียดสามารถอ่านได้ที่ http://localhost:82/JavaScript/JavaScript.html)

Tag

แท็ก (Tag) คือ คำสั่งพิเศษที่ใช้ในการกำหนดโครงสร้างและลักษณะการแสดงผลของเนื้อหาบนหน้าเว็บเพจ Tag จะถูกเขียนอยู่ใน เครื่องหมายน้อยกว่า < และเครื่องหมายมากกว่า>

Tag HTML แบ่งได้ 2 ลักษณะ

  • มีแต่ Tag เปิด แต่ไม่มี Tag ปิด , tag ที่สามารถใช้ได้มีดังนี้

    • <br>: ใช้สำหรับการขึ้นบรรทัดใหม่ (line break)
    • <hr>: ใช้สำหรับสร้างเส้นคั่นระหว่างบรรทัด (horizontal rule)
    • <img>: เป็นตัวเชื่อมโยงเพื่อให้รูปภาพถูกนำมาแสดงในหน้าเว็บไซต์เท่านั้น
    • <input>: ใช้สำหรับสร้างฟอร์มควบคุมต่างๆ เช่น ช่องข้อความ, ปุ่ม, ช่องทำเครื่องหมาย (checkbox), วิทยุ (radio button) โดยมี attribute type เป็นตัวกำหนดชนิดของ input
    • <meta>: ใช้สำหรับระบุข้อมูล metadata เกี่ยวกับเอกสาร HTML เช่น charset, viewport, keywords, description
    • <link>: ใช้สำหรับเชื่อมโยงไปยัง external resources ต่างๆ เช่น ไฟล์ CSS, favicon
    • <area>: ใช้ภายใน <map> tag เพื่อกำหนดพื้นที่ที่คลิกได้บน image map
    • <col> และ <colgroup>: ใช้สำหรับกำหนดคุณสมบัติของคอลัมน์ในตาราง (มักใช้ร่วมกับ <table>)
    • <embed>: ใช้สำหรับฝัง external application หรือ interactive content (เช่น Flash, PDF)
    • <keygen> (เลิกใช้แล้วใน HTML5): ใช้สำหรับสร้างคู่คีย์สำหรับฟอร์ม
    • <source>: ใช้ภายใน <picture>, <audio>, หรือ <video> เพื่อระบุแหล่งที่มาของสื่อต่างๆ
    • <track>: ใช้ภายใน <video> หรือ <audio> เพื่อระบุไฟล์คำบรรยาย (subtitles) หรือคำอธิบายอื่นๆ
    • <wbr>: ใช้เพื่อกำหนดจุดที่เบราว์เซอร์สามารถตัดคำได้หากจำเป็น

      • <head>: ส่วนที่เก็บข้อมูลเกี่ยวกับเอกสาร เช่น title, metadata, link ไปยัง CSS (เปิดด้วย <head> และปิดด้วย </head>)
      • <body>: ส่วนที่แสดงเนื้อหาหลักของหน้าเว็บ (เปิดด้วย <body> และปิดด้วย </body>)
      • <title>: กำหนดชื่อเรื่องที่จะแสดงบนแท็บเบราว์เซอร์หรือแถบชื่อ (เปิดด้วย <title> และปิดด้วย </title>)

      • <h1> ถึง <h6>: หัวเรื่องระดับต่างๆ (heading) (เปิดด้วย <h1> ถึง <h6> และปิดด้วย </h1> ถึง </h6>)

      • <a>: สร้างลิงก์ (anchor) (เปิดด้วย <a> และปิดด้วย </a>) โดยมี attribute href กำหนดปลายทางของลิงก์
      • <strong>: เน้นข้อความให้เป็นตัวหนา (strong emphasis) (เปิดด้วย <strong> และปิดด้วย </strong>)
      • <em>: เน้นข้อความให้เป็นตัวเอียง (emphasis) (เปิดด้วย <em> และปิดด้วย </em>)
      • <ul>: รายการแบบไม่มีลำดับ (unordered list) (เปิดด้วย <ul> และปิดด้วย </ul>) ภายในมี <li> (list item)
      • <ol>: รายการแบบมีลำดับ (ordered list) (เปิดด้วย <ol> และปิดด้วย </ol>) ภายในมี <li> (list item)
      • <li>: รายการย่อยใน <ul> หรือ <ol> (list item) (เปิดด้วย <li> และปิดด้วย </li>)

      • <tr>: แถวในตาราง (table row) (เปิดด้วย <tr> และปิดด้วย </tr>)
      • <th>: หัวตาราง (table header) (เปิดด้วย <th> และปิดด้วย </th>)
      • <td>: ช่องข้อมูลในตาราง (table data) (เปิดด้วย <td> และปิดด้วย </td>)

      • <form>: สร้างฟอร์มสำหรับรับข้อมูลจากผู้ใช้ (form) (เปิดด้วย <form> และปิดด้วย </form>)

      • <select>: กล่องตัวเลือกแบบ dropdown (select) (เปิดด้วย <select> และปิดด้วย </select>) ภายในมี <option> (option)
      • <textarea>: ช่องสำหรับพิมพ์ข้อความหลายบรรทัด (text area) (เปิดด้วย <textarea> และปิดด้วย </textarea>)
      • <button>: ปุ่ม (button) (เปิดด้วย <button> และปิดด้วย </button>)

    • สื่อ: , tag ที่สามารถใช้ได้มีดังนี้

      • <audio>: ฝังไฟล์เสียง (audio) (เปิดด้วย <audio> และปิดด้วย </audio>)

    • การจัดโครงสร้างเชิงความหมาย (Semantic HTML5): , tag ที่สามารถใช้ได้มีดังนี้

      • <article>: เนื้อหาที่เป็นเอกเทศและสามารถนำไปใช้ซ้ำได้ (article) (เปิดด้วย <article> และปิดด้วย </article>)
      • <aside>: เนื้อหาที่เกี่ยวข้องแต่แยกออกจากเนื้อหาหลัก (aside) (เปิดด้วย <aside> และปิดด้วย </aside>)
      • <nav>: ส่วนนำทาง (navigation) (เปิดด้วย <nav> และปิดด้วย </nav>)
      • <section>: ส่วนของเนื้อหาที่มีความเกี่ยวข้อง (section) (เปิดด้วย <section> และปิดด้วย </section>)
      • <header>: ส่วนหัวของเอกสารหรือส่วนของเนื้อหา (header) (เปิดด้วย <header> และปิดด้วย </header>)
      • <footer>: ส่วนท้ายของเอกสารหรือส่วนของเนื้อหา (footer) (เปิดด้วย <footer> และปิดด้วย </footer>)
      • <main>: เนื้อหาหลักของเอกสาร (main content) (เปิดด้วย <main> และปิดด้วย </main>)

หมายเหตุ ใน HTML5 tag <br> โดยตัวมันเอง ไม่มี attributes ที่เฉพาะเจาะจง แต่สามารถใช้งาน global attributes ได้เหมือนกับแท็ก HTML อื่นๆ และ attribute clear เป็น attribute ที่เลิกใช้แล้ว

global attributes ที่สามารถใช้กับ tag <br> มีดังนี้

  • id: กำหนด ID ที่ไม่ซ้ำกันให้กับ element
  • class: กำหนด class หนึ่งหรือมากกว่าให้กับ element (ใช้สำหรับการจัดรูปแบบด้วย CSS)
  • style: กำหนด inline CSS ให้กับ element
  • title: กำหนดข้อความเพิ่มเติมเกี่ยวกับ element ซึ่งมักจะแสดงเป็น tooltip เมื่อนำเมาส์ไปวาง
  • lang: กำหนดภาษาของเนื้อหาใน element
  • dir: กำหนดทิศทางการแสดงผลของข้อความ (เช่น ltr สำหรับซ้ายไปขวา, rtl สำหรับขวาไปซ้าย)
  • accesskey: กำหนดแป้นพิมพ์ลัดเพื่อเข้าถึง element
  • tabindex: กำหนดลำดับการ focus เมื่อใช้ปุ่ม Tab
  • draggable: กำหนดว่า element สามารถลากได้หรือไม่
  • hidden: กำหนดให้ element ถูกซ่อนไว้
  • spellcheck: กำหนดว่าควรตรวจสอบการสะกดคำใน element หรือไม่
  • translate: กำหนดว่าควรแปลเนื้อหาของ element หรือไม่
  • data-*: ใช้สำหรับเก็บข้อมูลส่วนตัวที่กำหนดเองสำหรับ element

    <input>

    <input> ใช้สำหรับสร้างฟอร์ม ซึ่ง ฟอร์ม ใช้ tag <form action=""> ... </form> ครอบ tag <input> เพื่อควบคุม tag <input> ต่างๆ เช่น ช่องกรอกข้อความ, ปุ่มกด, ช่องทำเครื่องหมาย (checkbox), วิทยุ (radio button) โดยมี attribute type เป็นตัวกำหนดชนิดของ input

    <input>: มี Attribute type ดังนี้

  • text: ช่องข้อความบรรทัดเดียว สำหรับป้อนข้อความทั่วไป (เป็นค่าเริ่มต้นหากไม่ระบุ type)
  • password: ช่องสำหรับป้อนรหัสผ่าน ข้อความที่ผู้ใช้พิมพ์จะถูกแสดงเป็นเครื่องหมายจุดหรือดอกจัน เพื่อป้องกันการมองเห็น
  • submit: ปุ่มสำหรับส่งฟอร์มไปยังเซิร์ฟเวอร์
  • reset: ปุ่มสำหรับรีเซ็ตค่าทั้งหมดในฟอร์มกลับเป็นค่าเริ่มต้น
  • radio: ปุ่มตัวเลือกแบบวงกลม ให้ผู้ใช้เลือกได้เพียงตัวเลือกเดียวจากกลุ่มที่มี name เดียวกัน
  • type checkbox: ช่องทำเครื่องหมายสี่เหลี่ยม ให้ผู้ใช้เลือกได้หลายตัวเลือกจากกลุ่มเดียวกัน
  • hidden: ช่องที่ซ่อนอยู่ ไม่แสดงผลบนหน้าเว็บ มักใช้เพื่อส่งข้อมูลที่เบื้องหลังโดยผู้ใช้ไม่ต้องเห็นหรือแก้ไข
  • file: ช่องสำหรับให้ผู้ใช้อัปโหลดไฟล์จากเครื่องของตน
  • image: แสดงเป็นรูปภาพและทำหน้าที่เหมือนปุ่ม submit เมื่อคลิก จะส่งพิกัดที่คลิกไปยังเซิร์ฟเวอร์ (ต้องมี src attribute กำหนดรูปภาพ)
  • color: ตัวเลือกสี ให้ผู้ใช้เลือกสีจากตัวเลือกสี
  • date: ช่องสำหรับเลือกวันที่ (ปี เดือน วัน)
  • datetime-local: ช่องสำหรับเลือกวันที่และเวลา (ปี เดือน วัน ชั่วโมง นาที) โดยไม่มี Timezone
  • datetime-offset: ช่องสำหรับเลือก วันที่ (ปี เดือน วัน), เวลา (ชั่วโมง นาที), และมีข้อมูล Timezone โดย Timezone จะถูกระบุเป็น Offset จาก UTC (เช่น +07:00 หรือ -05:00)
  • time: ช่องสำหรับเลือกเวลา (ชั่วโมง นาที)
  • month: ช่องสำหรับเลือกเดือนและปี
  • week: ช่องสำหรับเลือกสัปดาห์และปี
  • email: ช่องสำหรับป้อนอีเมล เบราว์เซอร์ส่วนใหญ่จะตรวจสอบรูปแบบอีเมลเบื้องต้น
  • tel: ช่องสำหรับป้อนหมายเลขโทรศัพท์ เบราว์เซอร์บางตัวอาจแสดงแป้นตัวเลขบนอุปกรณ์พกพา
  • number: ช่องสำหรับป้อนตัวเลข สามารถกำหนดค่าต่ำสุด (min), ค่าสูงสุด (max), และขั้น (step) ได้
  • range: แถบเลื่อนสำหรับเลือกค่าในช่วงที่กำหนด (ต้องมี min และ max)
  • search: ช่องสำหรับป้อนคำค้นหา ลักษณะการแสดงผลอาจแตกต่างจาก text: เล็กน้อย (เช่น มีปุ่มล้างข้อมูล)
  • url: ช่องสำหรับป้อน URL เบราว์เซอร์ส่วนใหญ่จะตรวจสอบรูปแบบ URL เบื้องต้น

    • text: ช่องข้อความบรรทัดเดียว สำหรับป้อนข้อความทั่วไป (เป็นค่าเริ่มต้นหากไม่ระบุ type)

    • ความสูง: ความสูงของ Content Box <input type="text"> จะถูกกำหนดโดย ขนาดตัวอักษรเริ่มต้น (default font size) และ padding ที่เบราว์เซอร์กำหนดไว้ ซึ่งโดยทั่วไปจะเพียงพอสำหรับข้อความบรรทัดเดียว

    • ขนาด Font: หากคุณไม่ได้กำหนด font-size ด้วย CSS, เบราว์เซอร์จะใช้ ขนาดตัวอักษรเริ่มต้น (default font size) ซึ่งส่วนใหญ่มักจะอยู่ที่ 16 พิกเซล (px)

    attribute enctype คือ ประเภทของการเข้ารหัส ที่ใช้เมื่อส่งข้อมูลของ Form ไปยังเซิร์ฟเวอร์

    • application/x-www-form-urlencoded (ค่าเริ่มต้น):
      • ลักษณะการทำงาน: ข้อมูล Form จะถูกเข้ารหัสเป็นคู่ของชื่อตัวแปรและค่า (name=value) โดยแต่ละคู่จะถูกคั่นด้วยเครื่องหมาย & และช่องว่างจะถูกแทนที่ด้วยเครื่องหมาย + ส่วนอักขระพิเศษอื่นๆ จะถูกเข้ารหัสเป็นเปอร์เซ็นต์ (%) ตามด้วยรหัส ASCII
      • การใช้งาน: เหมาะสำหรับ Form ที่ส่งข้อมูลข้อความธรรมดา (เช่น ข้อความในช่อง Input, Select, Textarea) และไม่มีการอัปโหลดไฟล์
      • ข้อจำกัด: ไม่เหมาะสำหรับการส่งไฟล์ เนื่องจากไฟล์จะไม่ถูกเข้ารหัสอย่างถูกต้อง
    • multipart/form-data:
      • ลักษณะการทำงาน: ข้อมูล Form จะถูกแบ่งออกเป็นส่วนๆ (multipart) โดยแต่ละส่วนจะมีส่วนหัวที่ระบุชื่อตัวแปร, ประเภทเนื้อหา (Content-Type), และข้อมูลของ Field นั้นๆ
      • การใช้งาน: จำเป็นต้องใช้ เมื่อ Form มี tag input type="file" เพื่อให้ไฟล์สามารถถูกส่งไปยังเซิร์ฟเวอร์ได้อย่างถูกต้อง นอกจากนี้ยังสามารถใช้กับ Form ที่มีข้อมูลจำนวนมากหรือข้อมูลที่ไม่ใช่ข้อความล้วนๆ ได้
      • ข้อดี: รองรับการอัปโหลดไฟล์และข้อมูลที่ไม่ใช่ข้อความ
      • ข้อเสีย: รูปแบบการเข้ารหัสมีความซับซ้อนกว่า application/x-www-form-urlencoded และอาจใช้ทรัพยากรมากกว่าในการประมวลผลฝั่งเซิร์ฟเวอร์
    • text/plain:
      • ลักษณะการทำงาน: ข้อมูล Form จะถูกส่งเป็นข้อความธรรมดา โดยไม่มีการเข้ารหัสพิเศษใดๆ ชื่อตัวแปรและค่าจะถูกคั่นด้วยเครื่องหมาย = และแต่ละคู่จะถูกคั่นด้วยการขึ้นบรรทัดใหม่
      • การใช้งาน: ไม่ค่อยได้ใช้ใน Form ทั่วไป มักจะใช้สำหรับการทดสอบหรือในกรณีที่ต้องการส่งข้อมูลแบบข้อความดิบๆ
      • ข้อจำกัด: ไม่รองรับการอัปโหลดไฟล์และอาจมีปัญหาในการจัดการกับอักขระพิเศษ

    มาดูความหมายแต่ละตัวกันดังนี้

    • website=: ส่วนนี้คือชื่อของ query parameter ใน URL ครับ Query parameters ใช้สำหรับส่งข้อมูลจากฟอร์ม (หรือจากที่อื่น) ไปยังหน้าเว็บ เมื่อมีการ submit ฟอร์ม (ในกรณีที่เราคุยกันเรื่อง ) ข้อมูลที่อยู่ในช่อง ที่มี name="website" จะถูกส่งไปพร้อมกับ URL ในรูปแบบนี้
    • https%3A%2F%2F: ส่วนนี้คือ ค่า ของ query parameter website ครับ มันคือ URL https:// แต่ถูก URL-encoded ครับ URL encoding เป็นวิธีการแปลงอักขระพิเศษใน URL ให้ปลอดภัยสำหรับการใช้งานใน URL โดยที่ : ถูกแปลงเป็น %3A และ / ถูกแปลงเป็น %2F
    • langsmartit-kyhb.onrender.com: ส่วนนี้คือ โดเมน (domain) ของ URL ครับ มันระบุชื่อของเว็บไซต์ที่เรากำลังอ้างถึง
    • /: สัญลักษณ์ / นี้อาจจะหมายถึง path (เส้นทาง) ไปยังหน้าเว็บหรือไฟล์บนเว็บไซต์ แต่ในกรณีนี้ ดูเหมือนจะเป็นแค่สัญลักษณ์ / ที่ต่อท้ายโดเมน ซึ่งมักจะหมายถึงหน้าหลัก (root) ของเว็บไซต์
    • #: สัญลักษณ์ # นี้เรียกว่า hash หรือ fragment identifier ครับ มันใช้เพื่อระบุส่วนใดส่วนหนึ่งของหน้าเว็บ (เช่น anchor link) แต่ในกรณีนี้ เนื่องจากมันอยู่ท้าย URL ที่ส่งมาจากฟอร์มที่มี action="#" มันไม่ได้มีความหมายในการระบุส่วนใดส่วนหนึ่งของหน้าเว็บครับ มันเป็นผลจากการที่เรากำหนด action="#" ซึ่งบอกให้ฟอร์มส่งข้อมูลกลับมาที่หน้าเดิม

    • ฟรีและเปิดกว้าง (Open Source): ฟอนต์ทั้งหมดบน Google Fonts สามารถใช้งานได้ฟรี ทั้งสำหรับส่วนบุคคลและเชิงพาณิชย์
    • หลากหลายและมีคุณภาพ: มีฟอนต์ให้เลือกหลายร้อยแบบ ครอบคลุมหลายภาษาและสไตล์
    • ประสิทธิภาพสูง: ฟอนต์จาก Google Fonts ถูกออกแบบมาให้โหลดได้อย่างรวดเร็ว ทำให้เว็บไซต์ของคุณไม่ช้าลง
    • ใช้งานง่าย: มีเครื่องมือและโค้ดที่พร้อมใช้งาน ช่วยให้การนำฟอนต์ไปใช้เป็นเรื่องง่าย
    • รองรับทุกเบราว์เซอร์: ฟอนต์ถูกปรับแต่งให้แสดงผลได้ดีบนเบราว์เซอร์และอุปกรณ์ที่หลากหลาย

    เชื่อมโยงไปยัง Manifest File สำหรับ Progressive Web App (PWA):

    Web App Manifest File คืออะไร?

    Web App Manifest File คือไฟล์ JSON ที่ให้ข้อมูลเกี่ยวกับ PWA ของคุณกับเบราว์เซอร์ ซึ่งข้อมูลเหล่านี้จะถูกนำไปใช้เพื่อกำหนดลักษณะการทำงานและรูปลักษณ์ของ PWA เมื่อผู้ใช้เพิ่มแอปพลิเคชันของคุณไปยังหน้าจอหลัก (Home Screen) หรือเรียกใช้จากตัวเปิดแอปพลิเคชัน (App Launcher)

    ข้อมูลที่ Manifest File มักจะประกอบด้วย ได้แก่:

    • name: ชื่อเต็มของแอปพลิเคชัน
    • short_name: ชื่อย่อที่ปรากฏบนหน้าจอหลัก
    • start_url: URL ที่จะเปิดขึ้นเมื่อผู้ใช้เรียกใช้แอป
    • display: โหมดการแสดงผลของแอป (เช่น fullscreen, standalone, minimal-ui, browser)
    • background_color: สีพื้นหลังของหน้าจอเปิดตัว (splash screen)
    • theme_color: สีธีมของแอปพลิเคชัน (เช่น สีของแถบสถานะของเบราว์เซอร์)
    • icons: อาร์เรย์ของวัตถุที่ระบุขนาดและที่ตั้งของไอคอนแอปพลิเคชันในขนาดต่างๆ
    • description: คำอธิบายสั้นๆ ของแอป
    • orientation: ทิศทางเริ่มต้นของหน้าจอ (เช่น portrait, landscape)

    ทำไม Manifest File ถึงสำคัญ?

    Manifest File เป็นหัวใจสำคัญที่ทำให้ PWA สามารถมอบประสบการณ์ที่ใกล้เคียงกับแอปพลิเคชัน Native ได้ เพราะมันเป็นส่วนที่:

    • ทำให้สามารถ "Add to Home Screen" ได้: เบราว์เซอร์จะอ่าน Manifest File เพื่อแสดงตัวเลือกให้ผู้ใช้สามารถติดตั้ง PWA ของคุณไปยังหน้าจอหลักได้
    • สร้าง Splash Screen: เมื่อผู้ใช้เปิด PWA เบราว์เซอร์จะใช้ name, background_color และ icons จาก Manifest File เพื่อสร้างหน้าจอเริ่มต้น (splash screen) ที่สวยงาม ทำให้การเปิดแอปดูรวดเร็วและเป็นมืออาชีพมากขึ้น
    • กำหนดรูปลักษณ์และการทำงานของแอป: display, theme_color และ orientation จะช่วยกำหนดว่า PWA ของคุณจะแสดงผลอย่างไรเมื่อเปิดใช้งาน และช่วยให้ PWA กลมกลืนไปกับระบบปฏิบัติการของผู้ใช้มากขึ้น
    • เพิ่ม SEO และการค้นพบ: การมี Manifest File ที่ถูกต้องช่วยให้เครื่องมือค้นหาและแพลตฟอร์มต่างๆ เข้าใจ PWA ของคุณได้ดีขึ้น ซึ่งอาจช่วยเพิ่มการมองเห็นและการค้นพบได้

    วิธีเชื่อมโยง Manifest File เข้าสู่เว็บไซต์ของคุณ

    การเชื่อมโยง Manifest File เข้ากับหน้าเว็บของคุณนั้นง่ายดายมาก เพียงแค่เพิ่มแท็ก <link> เพียงบรรทัดเดียวในส่วน <head> ของไฟล์ HTML ทุกหน้าที่คุณต้องการให้เป็นส่วนหนึ่งของ PWA

    • สร้าง Manifest File: ขั้นแรก คุณต้องสร้างไฟล์ manifest.json (หรือชื่ออื่นที่คุณต้องการ เช่น app.webmanifest) และวางไว้ที่ไดเรกทอรีรูท (root directory) ของเว็บไซต์ของคุณ ไฟล์นี้ควรมีโครงสร้าง JSON ดังตัวอย่าง:
      • JSON
                            
                          {
                            "name": "My Awesome PWA",
                            "short_name": "Awesome PWA",
                            "start_url": ".",
                            "display": "standalone",
                            "background_color": "#ffffff",
                            "theme_color": "#2196F3",
                            "description": "A fantastic Progressive Web App example.",
                            "icons": [
                              {
                                "src": "/images/icons/icon-192x192.png",
                                "sizes": "192x192",
                                "type": "image/png"
                              },
                              {
                                "src": "/images/icons/icon-512x512.png",
                                "sizes": "512x512",
                                "type": "image/png"
                              }
                            ]
                          }
    • เชื่อมโยงใน HTML: จากนั้น ให้เพิ่มแท็ก <link> ในส่วน <head> ของไฟล์ HTML ของคุณ:
      • rel="manifest": แอตทริบิวต์นี้ระบุว่าไฟล์ที่เชื่อมโยงคือ Web App Manifest
      • href="/manifest.json": ระบุที่อยู่ของไฟล์ Manifest ของคุณ แนะนำให้วางไว้ที่ root directory ของโปรเจกต์เพื่อให้เข้าถึงได้ง่ายและถูกต้อง
      Link Manifest File
                              
                            <!DOCTYPE html>
      
                            <html lang="en">
      
                            <head>
      
                                <meta charset="UTF-8">
                                <meta name="viewport" content="width=device-width, initial-scale=1.0">
      
                                <title>Link Manifest File</title>
      
                                <link rel="manifest" href="/manifest.json">
                                <meta name="theme-color" content="#2196F3">
                            </head>
      
                            <body>
      
                                <h1>Welcome to My PWA!</h1>
                                <p>This is a Progressive Web App.</p>
                            </body>
      
                            </html>

      ข้อควรพิจารณาเพิ่มเติม

      • Service Worker: Manifest File ทำงานร่วมกับ Service Worker ซึ่งเป็นสคริปต์ที่จัดการการแคช (caching) และการทำงานแบบออฟไลน์ของ PWA อย่าลืมว่าการมีแค่ Manifest File อย่างเดียวไม่เพียงพอที่จะทำให้ PWA ทำงานแบบออฟไลน์ได้ คุณต้องมีการลงทะเบียน Service Worker ด้วย
      • HTTPS: PWA ต้องการการเชื่อมต่อแบบ HTTPS เพื่อความปลอดภัยและเพื่อให้ Service Worker ทำงานได้อย่างถูกต้อง
      • ทดสอบ PWA ของคุณ: ใช้เครื่องมือสำหรับนักพัฒนาซอฟต์แวร์ของเบราว์เซอร์ (เช่น Lighthouse ใน Chrome DevTools) เพื่อตรวจสอบว่า Manifest File ของคุณได้รับการเชื่อมโยงอย่างถูกต้องและ PWA ของคุณมีคุณสมบัติตรงตามเกณฑ์ที่กำหนด
